# SpeakType v3.0.1

## 听写与编辑

主窗口采用 macOS 毛玻璃材质和原生工具栏，颜色随系统切换明暗主题。录音状态沿用浮层的波形和图标。最终文本获得主要编辑空间，原始转写可以展开或收起。麦克风、语音模型、语言模型、插入权限和快捷键状态合并为一行准备信息，可以查看完整详情并直接打开准备设置。

录音、停止、取消、原生文字编辑、undo/redo、复制、目标应用选择、润色、翻译和快捷键继续通过实际原生控件工作。主窗口录音生成可以检查的结果，全局快捷键使用录音开始时记录的目标输入位置。

麦克风准备期间可以取消。设备超过八秒仍未开始采集时，窗口显示具体错误并继续响应操作；取消后可以立即重新开始。

## 热词词典

词典使用原生毛玻璃侧栏、词语列表和详情区域。原有自定义词典中的词语也在这里显示，可以编辑、暂停、删除和检查冲突。每条词语保存标准拼写、最多八种常见误识别写法，以及可选的应用和场景范围。词典支持新增、修改、启停、删除、搜索和状态筛选。学习候选可以单独检查。JSON 导入会检查完整文件，字段错误不会导致部分保存；导出和重新导入保留启用、停用、待确认状态及每条错误写法的批准信息。

“纠错测试”接收转写文字，使用与实际听写相同的原有纠错规则、热词规则和处理顺序，显示输出和逐条修改。应用与场景可以分别指定，便于检查范围。这个区域用于检查文字替换；录音效果通过新的听写结果检查。

未保存的词条草稿在当前应用运行期间保留。切换条目、刷新、关闭与重新打开词典继续保留草稿。退出应用前，可以返回词典保存，或者明确舍弃草稿。

选择最终文本中的术语并点击“记住这个词”，即可保存标准拼写和常见误识别。再次保存同一个词语会保留已有错误写法和范围。自动学习与历史保存分别由偏好设置控制。

## 识别与纠错

Qwen3-ASR 通过实际支持的 `system_prompt` 参数接收 `Vocabulary: term1, term2.`。流式预览和最终识别使用相同参数构造。旧版自定义词典也提供识别提示。每次请求受词语数量和完整提示长度限制；手动词条和符合当前应用范围的条目获得优先选择。

明确的误识别写法在本地进行一次替换。较长词组优先，输出保留用户指定的大小写，英文术语可以紧邻中文文字。保存时会报告相互冲突的错误写法，已有冲突规则保留原文；英文缩写和词语内部的子字符串得到保护。每条学习别名单独保存置信度和批准状态，新增的学习写法使用自己的分数。用户明确保存或启用词条时，当前写法会得到批准。暂停词条同时停止该词条的识别提示和纠错；后续学习保留暂停状态。删除后，自动学习会继续忽略该词语；明确手动添加或导入可以恢复使用。

新增、编辑、改名、启停、删除和学习都在文件成功保存后更新当前词库。保存失败会保留原有内容，便于处理错误后重新操作。

历史记录保留原始识别、选中的识别提示、最终文本和明确的纠错记录。编辑最终文本或重新打开记录时，这些信息继续保留。完整历史提供热词详情，并能把所选记录打开到听写编辑区。所有模型推理、原生控件与并发取消验证分别记录检查范围。

## 调研依据

- [Superwhisper 的 Vocabulary 文档](https://superwhisper.com/docs/get-started/interface-vocabulary) 分开说明词汇提示与识别后替换，并说明提示过多会干扰识别。这支持有限提示与明确纠错同时存在的设计。
- [Wispr Flow 的词典文档](https://docs.wisprflow.ai/articles/4052411709-teach-flow-your-words-with-the-dictionary) 说明专名、纠错、学习开关和词条管理。这支持从用户修改进入可管理词条的流程。
- [Google Cloud Speech 模型适配文档](https://docs.cloud.google.com/speech-to-text/docs/adaptation-model) 说明词汇倾向同时影响漏识别和误识别。因此验证同时包含专名、普通句子和静音。

## 验证范围

`scripts/validate_hotword_pipeline.py` 使用实际文件和 Qwen3-ASR 模型，检查参数支持、模型提示中的词汇、文件与内存音频一致性、普通句子、英文专名、中文专名、静音和预览完成后的推理锁释放。音频来源为 macOS 内置语音合成。样例对比用于确认这些输入的行为，尚未构成不同说话人和真实噪声环境的准确率统计。

`scripts/validate_v301_integration.py` 检查实际识别经应用进入历史、原始文字保留、提示和修改记录保存、记录选择和编辑、词语即时生效、暂停、总开关与应用范围。

`scripts/validate_hotword_persistence.py` 使用实际文件权限拒写和文件替换错误，检查内存、原文件及重新加载结果的一致性；同时检查删除后学习、原有词典覆盖和逐条别名批准。

`scripts/validate_main_window.py`、`scripts/validate_studio.py` 和 `scripts/validate_vocabulary_workspace.py` 检查实际 AppKit 控件、原生文字编辑、词语操作、持久保存、草稿、中英文界面与窗口生命周期。

`scripts/validate_core.py` 和 `scripts/validate_operation_commits.py` 使用实际文件与并发工作线程检查核心行为、原子写入、取消与旧结果拒绝。构建脚本检查内置依赖执行、macOS 最低版本、动态库、源码一致性和严格代码签名。

## 安装

需要搭载 Apple Silicon 的 Mac，系统为 macOS 14 或更高版本。下载 `SpeakType-3.0.1.dmg` 并把 SpeakType 拖动到 Applications。应用包含 Python 与运行依赖，语音模型和可选的 Ollama 模型通过准备设置管理。默认语音识别在本机运行；如果自行配置远程 Ollama 地址，文字处理请求会发送到所选地址。

## English

SpeakType 3.0.1 introduces a compact native writing window with macOS materials, a system toolbar, adaptive light and dark appearance, and expandable original transcription. The recording state shares its waveform and icons with the floating overlay. Manage preferred spellings, multiple misspellings, application/context limits, enabled and paused entries, learned candidates, and JSON import/export in a native split view. Test saved replacement rules with current dictation settings, or save a word directly from selected final text. Unsaved vocabulary drafts survive navigation and closing the window during the current session.

Qwen3-ASR receives bounded `Vocabulary` prompts through its actual `system_prompt` input, shared by preview and final recognition. Explicit aliases run locally after recognition with exact casing, longer-phrase priority and a single replacement pass. The vocabulary editor also manages words from the existing dictionary. Paused entries stay paused when learning arrives, and deleted terms stay excluded from automatic learning. Each learned misspelling has its own approval state and confidence. The text test shares the actual dictation correction order, including saved correction rules.

History retains original recognition, selected hints, final text and applied changes through editing and reopening. Validation uses real AppKit controls, actual files, real concurrent operations and the local ASR model. Audio comparison fixtures come from macOS speech synthesis; they establish behavior on those inputs rather than a population accuracy estimate.

# SpeakType v2.2.0 Release Notes

SpeakType v2.2.0 introduces local adaptive hotwords. The feature is built around post-edit learning: after SpeakType inserts dictated text, it briefly observes only that inserted span in the same focused input field. If the user edits that span, the local Ollama model classifies the change and extracts durable terminology facts such as technical names, acronyms, code identifiers, proper nouns, and exact spelling or capitalization preferences.

The learned terms are stored locally in `~/.speaktype/hotwords.json`. They are not uploaded, synced, or used for telemetry. SpeakType ignores unrelated typing, pure append-only edits, app switches, unreadable input fields, and password-like targets where Accessibility does not expose text.

Hotwords are not unconditional replacements. On the next dictation, SpeakType selects a compact active context by app, scene, language, observation count, and confidence. That context is passed into Qwen3-ASR when the installed mlx-audio API supports `context`, and the same term list is given to the local polish and translation prompts so exact spellings are preserved when those terms are actually present. High-confidence wrong-to-right pairs can also be promoted into the existing correction store, keeping deterministic corrections separate from ASR biasing.

Desktop validation found and fixed an Accessibility edge case where TextEdit exposed its focused text area through the frontmost application's `AXFocusedUIElement` even when the system-wide focused element query returned empty. SpeakType now uses that fallback for insertion verification and post-insert edit observation.
